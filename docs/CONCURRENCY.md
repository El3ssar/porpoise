# Swift concurrency migration

Porpoise currently builds in Swift 5 language mode. W-188 enables complete checking in an **independent source snapshot**, rather than changing release settings. A successful checked build means the compiler finished; it does not mean warning-free or race-free. The remaining diagnostics are migration work, including warnings in test fixtures and SwiftTerm.

## Reproduce and retain evidence

```sh
scripts/audit-concurrency.sh /absolute/path/to/new-evidence-directory
python3 scripts/concurrency-diagnostics.py /absolute/path/to/new-evidence-directory
```

The audit copies tracked and nonignored untracked working files into a unique `.build/concurrency-audit/` directory, retaining the dirty working tree's changes. It records the source HEAD, dirty flag, toolchain, exact command, exit status and timestamps. `build.log` is unfiltered. `diagnostics.csv` and `diagnostics.json` retain each file:line:column, message, severity, occurrence count, risk, ownership assumption and next step. Duplicate target compilations count once per exact diagnostic; raw occurrence counts remain available. Unlocated driver warnings are retained as `<driver>`; unknown sites receive P1 review, never an automatic exemption. `files.md` groups the complete inventory for navigation.

The completed final W-188 audit retained **2,263 unique warnings (3,999 raw occurrences), zero errors**, including 175 dependency warnings and 12 unrelated compiler warnings. Every retained warning has a resolvable source/dependency location; one interleaved build-progress truncation was recovered through a unique snapshot suffix and recorded in `location-recoveries.json`. These are diagnostic counts, not counts of confirmed races. The initial W-188 run used Apple Swift 6.4 (`swiftlang-6.4.0.34.1`), macOS 27 SDK, arm64, while retaining the package's Swift 5 mode and macOS 15 deployment target. Its 1,444 unique warnings were a **partial baseline**: a nonisolated nested DebugBridge menu walker caused an actor error before all tests compiled. Use the completed post-fix run for the full inventory; do not compare its total with that partial run as a percentage improvement. Team evidence lives under `.herdr-synapse/porpoise/artifacts/p10/robust/w188/`, outside versioned source.

The parser's routing is conservative prioritization, not proof that a warning is harmless. P1 means an unproved shared-state or async boundary to settle before Swift 6; P2 means an ownership contract, queue invariant, UI annotation or test harness migration; P3 is a retained upstream diagnostic. All diagnostics remain visible. An actor warning can expose a real bug, but duplicate warnings and missing annotations are not independent race reports.

## Highest-risk findings fixed in W-188

| Boundary | Failure mode | Change and verification |
| --- | --- | --- |
| `Sources/PorpoiseServices/Cloud/HTTPFileStream.swift:15`, delegate executor | `OperationQueue.underlyingQueue` does not retain its queue; assigning a temporary could leave an unsafe dangling reference. | Retain the executor for the session lifetime. Publish a checked-Sendable stream with immutable continuation using `makeStream`. Existing fake HTTP range, cancellation and streaming tests cover transport behavior. |
| `Sources/PorpoiseServices/Remote/FTPProvider.swift:67`, login update | A shared provider could format a new username with an old password during overlapping login and transfer configuration. | `FTPLoginState` locks the pair as one immutable snapshot. Credential persistence and UI run outside the lock. The concurrent regression checks 10,000 replacements/readbacks without mismatched pairs. |
| `Sources/PorpoiseServices/System/FinderSounds.swift:27`, global cache | Concurrent requests mutated the ID dictionary and last-request value without synchronization. | A checked-Sendable player locks cache creation and snapshots; playback occurs outside the lock. Silent fake endpoints test 3,000 concurrent requests, one creation per sound and exact playback counts. |
| `Sources/PorpoiseServices/Remote/RemoteFS.swift:187`, FTP/SSH prompts | Mutable callback globals did not express their UI actor requirement. | MainActor callbacks and prompt types; provider ingress either assumes the verified main-thread branch or synchronously dispatches to main. Existing fake login/host-key tests preserve prompt and persistence behavior. |
| `Sources/Porpoise/App/DebugBridge.swift:51`, distributed callback; `Sources/Porpoise/App/ServicesSetup.swift:17`, service callbacks | A notification/provider closure could enter UI code without main-actor isolation. The complete build also rejected the menu delegate walker. | MainActor bridge, menu command registry, dynamic menu delegate and explicit nested walkers; nonisolated notification ingress extracts only a String then delivers to MainActor. | `Sources/PorpoiseServices/Media/LocalFileServer.swift:60`, unchecked-Sendable lifecycle | The listener and port were outside the request queue, relying on callers serializing start/stop; preview teardown can overlap another caller. | A lifecycle lock serializes the entire start/stop transaction, including source selection and listener readiness. A queue-owned generation rejects late callbacks from stopped listeners. Queue callbacks never acquire the lifecycle lock. Tests check concurrent starts share one URL, overlapping stop/start, and restart after stop. Request/response state, connection limits and deadlines retain their queue ownership. |

These changes add no blanket unchecked conformances, preconcurrency imports, global strict-checking suppression or language-mode switch.

## Ranked remaining work

1. **P1: service facades and worker handoffs.** `Sources/PorpoiseServices/FileOperations/FileOperationsController.swift:7` and extensions, `Locations/SearchRunner.swift:8`, `DirectoryModel`, `CloudEditCoordinator`, `Cloud/Offline/CloudOffline.swift:41`, and the cloud backend facades carry mutable state between queues and actor tasks. Their main-thread conventions need compiler-visible ownership. Split each operation into a MainActor coordinator and immutable Sendable request/result; snapshot captured `var` values before dispatch. Cancellation, generation checks, progress and conflict replies must survive the split. Audit backend provider/quotas dictionaries and callback registration alongside the facade: annotating only its initializer does not establish ownership of later reads. Verify with fake servers, stale-completion/cancel/retry tests, then the full watchdog.
2. **P1: public global configuration and callback storage.** `Settings.shared/store/isTesting`, `ConnectionCredentials.s3Store`, `RemoteOpener.openFile/rewatchOnMain`, app roots and test overrides are not made safe by `nonisolated(unsafe)`. Separate immutable startup configuration from mutable runtime settings. Actor-isolate UI callbacks; use a locked value for configuration accessed by workers. Test overrides must be restored and tests serialized where ownership is process-wide. Do not claim an injected closure is Sendable without auditing its captures.
3. **P1/P2: media and network lifetime.** `VideoPreview`, `CloudPlaybackSession`, `StreamSession` and `LocalNetworkAccess` mix callbacks, worker processes, actor-owned UI and teardown. Compute Sendable scalars before the main hop instead of transferring AVFoundation/AppKit objects. Add generation-aware callback cancellation and an explicit teardown executor. Actor deinit support must be checked against the supported compiler/deployment combination before using it. A lock around server lifecycle does not establish the ownership of its clients.
4. **P2: serial queues and locks.** `TrashService`, journals, `OperationHistory`, `SaveWatcher`, archive metadata/cache, index crawlers and provider caches need field-by-field ownership documentation and Sendable callback contracts. A serial queue only protects fields when every access goes through it; shared static encoders/caches across instances require separate scrutiny. Prefer checked Sendable immutable values or `OSAllocatedUnfairLock` state before an audited unchecked wrapper. Preserve source-version checks, atomic publication, durable journal ordering and no-unconditional-save-back behavior.
5. **P2: parallel scans.** `NameIndexSearch` borrows column/scratch buffers inside a joined parallel region; distinct workers write distinct slices and the join bounds lifetime. `PhysicalTreeScanner` joins recursive parallel traversal. Express their scoped worker/cancellation contracts without transferring raw pointers beyond the join or adding a global search lock. Validate lifetime, cancellation, matching results and the existing performance workload before changing this path.
6. **P2: AppKit boundary migration.** Extend explicit MainActor ownership from the bridge/prompts into AppDelegate, services setup, menus, theme, window/view helpers and callback APIs. Move file/process work out before annotating coordinators. Verify menu/window/preview behavior and release compilation, not only the test-hook build. Never add `assumeIsolated` to an arbitrary callback: it requires an established main-thread executor contract.
7. **P2/P3: fixtures and dependency.** MainActor test classes, locked fake-server recorders, Sendable fixture closures and immutable subprocess results should make tests model the production boundary. SwiftTerm diagnostics require an upstream update or separately reviewed patch. Do not edit vendored code merely to reduce a count, or hide its warnings when evaluating readiness.

## Unchecked and unsafe declarations

Complete checking cannot establish safety inside `@unchecked Sendable` or `nonisolated(unsafe)`. The evidence inventory includes their source locations separately from compiler diagnostics. The contracts below are audit obligations, not a certification of every declaration:

| Family | Required invariant / migration target |
| --- | --- |
| `JobControl`, disk cancellation, reply/wake flags, byte budgets | All mutable cancellation/pause/reply state uses its lock; callbacks run after releasing locks. |
| `FileJob`, folder watchers, search crawlers and `StreamSession` | Worker/queue state stays on its executor; stop/finish is idempotent; no borrowed buffer or process handle outlives teardown. |
| Cloud clients/providers/content sources, account credentials, metadata caches | Cache/journal state is locked or actor-owned; async requests capture immutable auth/account identity; callbacks cannot mutate UI directly. |
| Journals, operation history, edit-session stores and range writers | Locks/serial queues cover reads and writes; persistent snapshots publish atomically; cross-instance static state has its own ownership. |
| OAuth loopback/listeners and `ConnectionMonitor` | Listener/connection lifecycle and callback ownership must be serialized, including cancellation/restart. |
| `NameIndex`, `Columns`, search specifications and index queries | Published storage is immutable, scratch writes disjoint and joined; predicates/cancellation captures have explicit transfer contracts. |
| Format/type/name caches and descriptor/trash caches | The same lock covers cache lookup, insertion, invalidation and any mutable formatter use. Returning a formatter outside its lock requires separate protection. |
| `HTTPFileStream.Streams` | Delegate registry dictionary uses its lock; published streams and continuations are immutable; URLSession delegates may arrive concurrently. |
| `LocalFileServer` | Lifecycle lock owns listener/port; request queue owns source/root, connections, tasks and timers. Callbacks never acquire lifecycle lock. |
| Unsafe test configuration and service callback statics | Initialize before publication or serialize overrides; restore after tests; migrate runtime callback storage to actor/locked ownership. |

Do not remove an unchecked declaration just because its diagnostic count is zero. Convert one family at a time, with an explicit inventory of protected fields and calls made while holding locks. Blocking synchronous-to-main prompt APIs need special care: callers must not hold a lock that main-actor UI needs.

## Rollout gates

First make the FileSystem and Core worker/value contracts explicit, then Services workers and actor facades, then the app and test harness. Re-run the isolated audit after each step. Migrate an individual target to Swift 6 only when its own diagnostics and downstream API boundaries are settled. Keep macOS 15 and supported toolchain builds in the matrix; the developer machine's newer SDK can expose additional actor contracts.

Each migration must pass focused regressions, strict formatting, release compilation, the full watchdog and the repository's >=92% coverage gate. The W-188 audit also exposed the menu registry walker; propagating that ownership required explicit actor contracts on the ShortcutSheet walker and MainMenu dynamic-menu delegate. Test execution under load and complete checking answer different questions; neither substitutes for the other. Thread Sanitizer stress runs are useful supplementary evidence for lock/lifecycle changes, but no TSan run is claimed for W-188.

Swift's [complete-checking guidance](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/enabledataracesafety/) and [incremental migration strategy](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/migrationstrategy/) describe enabling diagnostics before changing language mode. The ownership/risk judgments above come from Porpoise's source and retained build evidence.
