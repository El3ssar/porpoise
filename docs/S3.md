# S3-compatible locations

S3 uses the shared remote location, directory, Activity, transfer and conflict-policy engines. It connects directly to an S3 endpoint with Signature Version 4; no SDK, CLI or paid service is required.

A location identifies one bucket and an exact key prefix:

```
s3://my-bucket/path/?endpoint=https%3A%2F%2Fs3.eu-central-1.amazonaws.com&region=eu-central-1&account=ACCOUNT-UUID
```

The endpoint is the service root, without a bucket or path. Requests use path-style bucket addressing. AWS S3 uses a regional endpoint; MinIO uses its server address; Backblaze B2 uses its regional S3 endpoint; Cloudflare R2 uses the account's S3 endpoint and region `auto`. HTTPS is required except on loopback for local fixtures. Configure a bucket explicitly; this adapter does not enumerate accounts' buckets.

The connection manager supplies `S3Credentials.save(S3AccessKeys(accessKeyID:secretAccessKey:sessionToken:), accountID:)`. Access keys and optional temporary session tokens use the shared production Keychain / isolated-test-memory credential policy. Locations, saved profiles and transfer journals contain no secret access key or session token.

Prefixes appear as folders. Empty folders have zero-byte slash markers; removing an empty folder removes only its marker, so a concurrently arriving child remains safe. Keys are URI encoded without normalizing slashes. ListObjectsV2 pagination uses the shared pager and rejects repeated tokens. Object names must be safe single components before being materialized locally.

Downloads use conditional revision reads and the shared staged/range download engine. Files upload in 8 MiB parts above the multipart threshold, increasing the part size for very large files. The shared durable journal records the upload ID and acknowledged part ETags. Retrying the same operation UUID resumes with the same source fingerprint; an ambiguous completion is reconciled against operation metadata. The provider finds matching interrupted uploads automatically. Explicit abort removes the remote multipart session. A lost initiation response can leave an unknown incomplete upload; configure a bucket lifecycle rule to expire incomplete multipart uploads.

Same-connection file copies use server-side copy after the shared conflict decision. Rename/move are copy then conditional source deletion, with no deletion until the copies are acknowledged. Destination create and replace use conditional headers (including R2’s documented `cf-copy-destination-if-*` headers); incompatible services fail closed. S3 Last-Modified is server controlled: replacement with date preservation requested fails with an instruction to choose Content or Size comparison. Objects above 5 GiB use UploadPartCopy and conditional multipart completion. Servers must honor S3 source-revision conditions on copied parts. Bucket deletion, version-history management, ACL editing and region discovery are outside this adapter.

Local verification:

```
swift test --filter 'S3ProviderTests|CloudTinyRangeTests|CloudHTTPPipelineTests'
```

The loopback-only Python fixture independently verifies signatures, checks conditions and implements pagination, prefix markers, range downloads, server-side copies and multipart interruption/restart. The signer also passes AWS's published GET Object signature vector. No real account is contacted by these checks.
