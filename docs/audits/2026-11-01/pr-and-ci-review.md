## CI changes

- Dependency graph review runs when Swift manifests/lockfiles or external Action pins change, including version-specific manifests, flow-style steps and local composite actions. Unsupported key syntax and unreadable revisions fail closed. Source-only PRs no longer call an unavailable graph API. Pin integrity and the retained maintenance proposal still run on every PR. Actual dependency changes still require the repository's graph capability; disabling errors or lowering the vulnerability severity is not the fix. Vendored/tool-source changes remain explicit manual-review inputs.
- Swift Testing admission is bounded to six cases by default, with capability detection and a validated override. The verified toolchain default was effectively unlimited. XCTest's worker count is a different option. Isolation traits, stress/memory passes, assertions, discovery completion checking and the92% coverage gate remain.
- The harness performs one matching instrumented build, then discovers/runs with `--skip-build`. Previously repeated planning/rebuilds cost11–15 seconds in the retained runs. A tempting `swift test list` prebuild was rejected because Swift6.3.3 explicitly disables coverage for that operation.
- Optimized benchmark compiler state has a private, platform/toolchain/input-keyed cache with owned paths, exclusive locking and content-checked timestamps. Both source versions are still built and staged independently, all executable hashes/provenance remain checked, and every workload/measurement runs fresh. Cached timings or staged apps never substitute for a comparison.
- Completed CI retains source-tree evidence. Post-merge/release reuse requires exact build/test/security input identity, the actual successful gate jobs from the same run attempt, valid tested checkout parents, and maintainer-approved merge ancestry. A PR cannot certify changes to its own workflow/proof machinery. A newer matching-input failure vetoes older green evidence. API/shape/expiry/provenance failures fall back to full checks. README remains protected because the shortcut contract test reads it.
- Warning fixes restore actor and queue contracts, explicit unused results, and bounded callback ownership. The SwiftTerm generator writes its profile only into its own sandbox work directory; test coverage is not disabled. The accidentally tracked generated `default.profraw` is removed from the index, retained locally and ignored along with other generated profiles.
