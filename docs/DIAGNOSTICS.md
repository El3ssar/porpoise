# Local diagnostic events

`PorpoiseServices.DiagnosticStore` is the service API for a local support trace. The app keeps one store for the
process (`Diagnostics.shared`), records events at its main error sites, and offers them only through
**Help › Export Diagnostics…**: a window shows the reviewed snapshot exactly as it will be saved, and Save writes those
bytes to a file the user chooses. Nothing is persisted in the background or sent anywhere. Operation history remains
separate and is never included in an export.

## In the app

| Code | Recorded when | Failure category |
|---|---|---|
| `transfer.failed` | a copy or move ends with items it couldn't place (`FileOperationsController.ended`) | the first error's category |
| `provider.error` | a cloud service request fails, once per change of category per account; a success resets it (`CloudAccountStatus.record`) | the error's category; `authentication` when the service wants a new sign-in |
| `helper.failed` / `helper.unavailable` | the privileged helper fails a command / can't be reached (`PrivilegedHelper.run`) | `unknown` / `unavailable` |
| `app.unclean_exit` | at launch, when the previous run didn't quit normally (a crash, force quit or power loss) | `unknown` |

The unclean-exit check is one boolean in Porpoise's own preferences (`diagnostics.running`), set at launch and
cleared on quit. No crash report is read. Each cloud account's events share a random correlation, never its id.
A user's own cancel records nothing. The app's save replaces an existing file only after the save panel has asked.

## Privacy boundary

Events have exactly four fields: timestamp, a fixed event code, a coarse failure category, and a randomly generated
operation correlation. There is no message, arbitrary dictionary, path, URL, host, filename, provider/account ID,
command, error description, underlying error or raw error domain field. A correlation is generated by this API;
there is no initializer that accepts an account/file ID. An error is reduced immediately to a fixed category and
is not retained. Unknown errors become `unknown`, without their domain, type name or description.

The version/build fields accept only 1–4 dot-separated ASCII numeric components of at most four digits each.
Unexpected bundle metadata becomes `unknown` in its entirety. OS identity uses numeric OS components, with a
compile-time architecture label. No device/user name, environment, home path or working-directory data is read.
Do not pass user data as build metadata, or add freeform fields to the schema. Add a reviewed enum case instead.
This is exclusion by schema, rather than a regular expression that might miss a new token or filename format.

Schema version 2 codes are `persistence.write_failed`, `provider.connected`, `provider.disconnected`,
`subprocess.exited`, `helper.unavailable`, `recovery.started`, `recovery.finished`, and (new in 2) `transfer.failed`,
`provider.error`, `helper.failed` and `app.unclean_exit`. Failure categories are
`none`, `cancelled`, `permission`, `notFound`, `noSpace`, `network`, `authentication`, `conflict`, `timeout`,
`unavailable` and `unknown`. Classification uses only known Foundation domains/codes. It never retains `userInfo`.

## Recording and reviewing

```swift
let diagnostics = DiagnosticStore() // numeric bundle version/build and numeric OS identity
let operation = DiagnosticCorrelation()
diagnostics.record(.recoveryStarted, correlation: operation)
// On failure: classify an Error, without recording its description or context.
diagnostics.record(.persistenceWriteFailed, error: error, correlation: operation)
let reviewed = try diagnostics.preview(correlations: [operation])
// Present reviewed.text for inspection, then use a user-chosen new local filename.
try reviewed.write(to: chosenFileURL)
```

Recording is synchronous, thread-safe and best effort: a false return means no event was kept. Never let a
tracing failure replace the operation's own result. Reuse one generated correlation for related events; do not
encode a user's identity in event selection or version fields. `preview()` includes all retained events; an
explicit empty correlation set includes none. A reviewed export is immutable: events recorded later do not alter
the reviewed bytes. The file writer rejects non-file URLs, remote file hosts and existing files, and reports write
errors. It does not create missing parent folders. A failed write can leave a partial new file; report the error
and do not present that file as a completed export. A user-selected mounted filesystem can perform filesystem IO;
there is no HTTP client, upload API or automatic sharing in this service.

## Bounds and lifetime

Defaults are 256 events, 256 KiB for the complete encoded export including metadata/JSON syntax, and a 24-hour
review horizon. Limits clamp to 0–1000 events, 1 KiB–1 MiB and 1 second–7 days; a non-finite age uses 24 hours.
Zero events disables retention. On record/preview, expired events and events ahead of a rolled-back clock are
removed, then oldest events are removed until count/byte bounds hold. Age cleanup is access-driven, not a timer.
The buffer does not survive process exit. Explicitly saved exports remain at the user-chosen location; each
snapshot respects the byte cap, and saved files are not automatically deleted. `clear()` removes the current buffer. Keep a recorder's lifetime narrow where
possible; do not automatically export it on quit or on a crash.

The export JSON contains `schemaVersion`, `identity`, `generatedAt` and `events`. Dates are numeric milliseconds
since the Unix epoch. Only the retained events selected for review are included. No existing operation-history
file, preferences file, keychain item, native crash report or process sample is read or bundled.

## Validation and support

Run `swift test --filter DiagnosticsTests` for privacy, error classification, correlation/selection, count/byte/age
retention, concurrency, malformed metadata and exact-preview/local-file tests. The privacy fixture injects a
username path, a cloud filename, bearer/refresh tokens, account email, host credentials, URL query and nested error
text; none is present in the preview. Local export tests prove identical reviewed bytes and no overwrite. Network
URLs are rejected before file IO. Full validation still uses the watchdog, coverage, strict lint and shipping
product build documented in CONTRIBUTING.md.

Run `swift test --filter 'DiagnosticsInstrumentationTests|DiagnosticsExportWindowTests'` for the app's error sites: each
feeds personal data (user and file names, a token, an account id, a helper's paths) and checks none reaches the
export, and the window test checks the preview text and the saved bytes are the reviewed snapshot.

Any other UI that offers this trace must likewise show the exact preview and require the user's deliberate
save/share action. Native crash reports and Activity Monitor samples are separate, potentially sensitive artifacts;
never append them automatically. Do not promise source-level crash symbolication from these events alone.
