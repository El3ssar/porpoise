# W-133: Compact layout and metadata responsiveness

Scope: APP-1, APP-4 and APP-6 from the app audit. Product implementation is `90b6c94` plus themed asynchronous-page follow-up `f1ed58d`, with the independently reusable `DirectoryModel.rowsRevision` API in `b50cca2`. No merge or push was performed; lead-owned integration remains pending.

## Changes

- Compact keeps the widest displayed name/additional-role text as a scalar keyed by row revision, roles and the relative-date minute. Pure resize and live/saved zoom reuse it. Renames, filtering, new listings, fonts, displayed extensions, date/permission formatting and loaded tags/folder counts invalidate it. The existing per-string cache stays bounded. On this Services base, committing zoom still invokes the model's existing rebuild/sort; this change removes repeat text shaping across that synchronous commit, not the model rebuild itself. The timed live-preview probe excludes that save step; the regression test covers shaping reuse during saved zoom. Saved zoom can adopt the identical rows synchronously rebuilt while only icon size is committed.
- List drawing/geometry settings and container listing settings now have separate explicit routes. Terminal preferences, confirmations and app-library zoom leave ordinary folder rows alone, including hidden panes. Restore Defaults still refreshes all settings; sort/backup filtering and folder-size/expansion settings retain their model behavior.
- Tag-dot construction queues the common-tag intersection on a private queue and stops once it is empty. Dots show a loading state and accept edits after the answer arrives. Closing/discarding the view cancels remaining work. No xattr read occurs in menu construction.
- Properties displays a loading page immediately, reuses supplied `FileItem`s, and loads missing metadata, locked/extension/comment flags and volume capacity on its own private queue. Permissions reuses the loaded item. Closing cancels the pending load and prevents late UI updates. Existing explicit metadata-changing actions retain their behavior.

The tiny Services API overlaps perfcore's ownership; it was announced before editing and published as its own commit. All other product files are the announced app files. Perfcore approved the API in board #3198: when integrating with `06d5a2e`, preserve its lazy `rowFileKeys = nil` and keep `rowsRevision &+= 1` beside the row-index invalidation. The app cache does not depend on the key representation.

## Regression evidence

`swift test --filter PerformanceRoutingTests` passed six tests (22.167 s) before warning-only cleanup. The final frozen-image focused replay below retests the final source, including themed asynchronously loaded controls. The tests cover:

1. More than 50,000 distinct labels: resize, live zoom and committed zoom cause no additional text shaping; rename widens the column and filtering removes the frames.
2. Font, extension and additional-role formatting changes update Compact geometry.
3. An unrelated terminal preference, confirmation and library zoom cause zero rebuilds across visible and hidden folder panes; backup filtering and Restore Defaults still rebuild.
4. The tag reader runs off main and an empty first result stops a 100k-selection intersection after one read.
5. Asynchronous common-tag checks retain the intersection of different tag sets.
6. Properties construction finishes before the metadata result and preserves a supplied item that cannot be loaded from disk.

Text-shaping counts are test-hook-only instrumentation, excluded from ordinary release builds. There are no production time-threshold branches or timing-based test assertions. Measurements are AppKit layout and bitmap drawing probes, not attended UI/scrolling or compositor FPS proof.
